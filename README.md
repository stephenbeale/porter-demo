# Porter phone demo

Scan a vehicle service document with your phone. **Your personal details are redacted on the phone before anything is sent**: Tesseract (OCR in the browser) finds names, addresses, phone numbers, emails, card and account numbers, V5C references and signature lines; you check the boxes, tap to uncover any that are fine (like the garage's own address) and draw over anything missed. Only the redacted pages go to Claude, which reads the details and, as a second check, boxes any personal data still visible. Porter only takes vehicle paperwork: a page showing a person (face or body, detected on the phone with Human) is never sent, and anything that doesn't read like a car document gets an "are you sure?" first. After reading, Claude flags anything hateful, sexual, violent or of questionable legality, which is rejected and never saved. The on-phone work starts the moment a photo is added: first every page is turned upright (the thumbnail visibly turns), then each is read and checked, with a ✓ on its thumbnail, so Process usually goes straight to the check step. Pages are sorted into boxes by document as they're processed (by garage name, website, VAT or invoice number); a page that can't be placed goes in "Needs checking", and each document is then checked and sent on its own. PDFs can be added too ("Upload a PDF or file"): pdf.js turns each page into an image on the phone, up to 20 pages, and they go through the same redaction. The on-phone engines (about 14 MB) load from jsdelivr the first time and are cached. Then note what the mechanic told you but didn't write down ("the tyres will want doing by mid-November"): type or dictate it, Claude picks out the actions and dates, and you can export the reminders to your phone calendar (.ics). Work you did yourself can be logged too (words, plus photos of the part or receipt). Scans and notes build up into a history saved in your browser, one car at a time (the plate on the paperwork decides which car; you can add and switch cars) (personal data from the scans is never saved), and Selling mode turns that history into a sale summary for buyers, saved as a PDF. Every scan keeps its redacted pages automatically. Export makes one zip: a service history PDF laid out like the History page, and a folder per visit with its redacted pages, ready to save to Google Drive, Dropbox or OneDrive. Porter opens on History. After checking a scan's boxes you can keep a redacted copy (stored in IndexedDB) and attach it to the sale summary. Only your personal details are redacted; the registration, VIN and prices stay, as on the paper originals a buyer gets. Bring your own Anthropic API key. It is stored only in your browser's localStorage and sent only to api.anthropic.com. Blacked-out pages and advice notes go straight from your device to Anthropic. Dictation uses the browser's speech recognition, which in Chrome sends the audio to Google. A throwaway prototype; the real app keeps keys server-side. Generated from the private porter repo (web-demo/build.py).

On iPhone, add it to your Home Screen (Share → Add to Home Screen) and use it from there: Safari deletes a site's saved data after 7 days without a visit, but Home Screen apps keep theirs. Back up and Restore (under "Your car's history") move your history between browsers, phones or into the Home Screen app.

## Stack

A mobile web app (PWA) in plain JavaScript, hosted on GitHub Pages. Claude reads the paperwork; personal details are blacked out on the phone first, using OCR in the browser; a Cloudflare Worker sits in front of the AI for beta testers.

| Layer | What's used |
|---|---|
| **App** | One HTML file: plain JavaScript and CSS, no framework, no build step. An installable PWA (web app manifest and home-screen icons; no service worker yet, so it needs a connection), hosted on **GitHub Pages**. |
| **AI** | **Claude** via the Anthropic API: **Opus 5.5** reads each document into structured data (JSON schema output); **Haiku 5.5** sorts photo batches into visits and turns typed descriptions of work into line items. |
| **On the phone** | **Tesseract.js** (OCR) finds personal details to black out before anything is sent; **Human** (TensorFlow.js, WASM) spots people in photos; **pdf.js** turns PDFs into page images. |
| **Storage** | On the phone only: **localStorage** for history, **IndexedDB** for the kept, redacted pages. No server database. |
| **Exports** | Service history book PDF and zip built by the app's own code; **Google Drive** upload via Google Identity Services (`drive.file` scope); calendar reminders as **.ics**. |
| **Beta server** | **Cloudflare Worker** + **Workers KV** (porter repo, `worker/`): holds the API key, invite codes and **Google sign-in** (ID tokens checked against an email allowlist), per-tester spend caps, and **DVSA/DVLA** lookups for MOT history and tax status. |
| **Paused full version** | `porter/web`: **React 19 + TypeScript + Vite**, **Supabase** (auth, Postgres, storage), deployed on Cloudflare. |

**Beta testers** can sign in with Google or use an invite code instead of an API key, through the Porter beta server (the `worker/` folder in the private porter repo). It holds the key, caps spend, and adds **MOT history import**: every DVSA MOT test for a registration, plus DVLA road tax and MOT due dates. Set `BETA_SERVER` in `index.html` to the deployed Worker's URL, then send invite links like `?invite=<code>`. With `BETA_SERVER` empty, the page works as before with your own key.
